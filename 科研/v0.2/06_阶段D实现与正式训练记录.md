# v0.2 阶段 D：critic 预热与受控 PPO 微调

日期：2026-10-04（北京时间）。用户授权实现并启动 D。目标是在保留六组合来源互换能力的基础上，改善跑步、侧移和转向等困难动作的完成率。

## 起点与实现

C 完成 2,000 轮并通过完整六组合验证，各 500 条、83 个家族。成功率依次为 Human/G1/Roban→G1：93.2%/94.8%/95.8%；Human/G1/Roban→Roban：90.8%/93.2%/93.2%。最终权重作为固定动作均值基线，原结果保留。

D 新增 `active_adaptation/learning/xwbc_finetune.py`，复用已有 rollout、GAE、PPO 裁剪损失、环境/动作契约、checkpoint 和六组合评分。分阶段入口新增 `finetune`，配置为 `cfg/xwbc/v02/finetune.yaml`，继承 C 配置。

- 冻结三个命令 Encoder；本体 Encoder、共享主干、动作头和两个 critic 可训练。
- B/C 的 critic 没有训练，因此前 100 轮只进行价值学习，actor 均值参数保持逐值一致。
- B/C 的未训练标准差为 1；D 显式设置固定标准差 0.1，整轮不学习该参数。
- PPO 采用冻结 C 在相同实际状态、相同来源上的动作均值保持损失；权重 0.1，按各机型有效动作维度平均后对两机型等权。
- 两机型各一个环境池。每个环境槽固定来源 `env_id % 3`，reset 后保持分配，三来源每轮份额为 342/341/341 个环境。
- 新日志区分随机训练起点的回合成功统计和正式完整片段评分；每路记录实际采样数、奖励与结束/完成回合数。

## 短验证暴露的问题与修正

第一次正式规模工程检查使用 1 轮预热 + 2 轮 PPO。原先只在下一 minibatch 检查 KL 时，首个 actor 更新已经造成约 3.60 的 KL，超过目标 0.02。原检查会停止后续更新，但不能撤回已应用步长。该检查保留在 `stage_d_preparation/capacity/`，未用于正式权重初始化。

修正为记录 rollout 的旧动作均值，计算固定标准差高斯策略的解析 KL。每次 Adam 提议 actor 参数更新后，对参数增量进行逐次减半回溯，实际应用的 minibatch KL 须 ≤0.02；最多回溯 10 次。完全拒绝的 actor 步恢复其参数和 Adam 状态，critic 更新独立保留。接受的回溯相当于缩小当次 actor 的有效学习率。

带回溯的 `capacity_guarded/` 验证在每机型 1,024 环境下完成 1 轮 critic 预热与 2 轮 PPO。两轮各应用 12 个 actor 优化步，最大应用 KL 分别约 0.01748、0.01969。首轮预热的 actor 保持不变，critic 有更新，PPO 执行模块有更新，三个来源编码器保持不变；实际 checkpoint 的六路 CPU 重载逐值一致。

CPU 回归包括原有数据/评估语义、A/B/C 和 D 的冻结、预热、PPO、过冲回溯、拒绝步的优化器恢复、来源均衡、checkpoint 恢复及 D 同路基线比较。验证日志均在 `logs/v0.2/staged_run01/stage_d_preparation/`；最终汇总见其中的 `validation_summary.json`。

## 正式训练设置

| 项目 | 设置 |
|---|---:|
| 每机型环境数 | 1,024 |
| rollout | 32 步 |
| critic 预热 | 100 轮 |
| PPO | 500 轮 |
| 总更新目标 | 600 轮 |
| 总 transitions | 39,321,600 |
| actor 名义学习率 | 2e-5，受回溯约束 |
| critic 学习率 | 1e-4 |
| PPO epoch / minibatch | 3 / 8,192 |
| clip / KL 上限 | 0.1 / 0.02 |
| 固定动作标准差 | 0.1 |
| C 动作保持权重 | 0.1 |
| checkpoint 间隔 | 50 轮，以及预热结束时 |

每轮最多 12 个优化步，KL 限制可能减少实际步数。数据、上下文、动作接口和奖励沿用 C；不增加负载或域随机化。本轮是有界的微调试验，预热轮数和预算不代表预设收敛保证。

恢复从 D checkpoint 加载 actor、critic、优化器和 RNG，检查 C 基线摘要和配置兼容，重新开始仿真回合。正式运行从 C 权重新建 optimizer，不使用工程检查更新后的权重。
