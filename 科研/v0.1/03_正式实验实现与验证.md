# v0.1 正式实验实现与验证

日期：2026-10-01。用户明确本研究不需要负载模块，阶段安排以研究需求为准；实现采用 HEFT 环境上的无负载直接 PPO。

操作入口见 [正式实验使用说明](../../docs/xwbc正式实验.md)。机器可读验证汇总位于 [validation_summary.json](../../logs/v0.1/xwbc_validation/validation_summary.json)。本轮交付正式运行流程与脚本，已执行数据准备和有限预算验证。

## 实现内容

| 层次 | 实现 |
|---|---|
| 配对数据 | 固定一万条选样、动作家族隔离、三来源同步检查、分片编译、源摘要及目标资产版本记录 |
| 命令表示 | 人体已有骨架特征；机器人以当前资产 FK 构造空间特征；骨盆中心和朝向归一化，附加高度与转向角速度 |
| 环境 | 两个 HEFT 机型环境池；随机化注册表为空，关闭负载、额外质量、WPC、外力和放大力矩课程 |
| actor | 三来源编码器、两个本体编码器、共享 MLP 和两个原生动作维度输出头 |
| critic | 机型专用特权 critic；目标参考与 actor 输入分开 |
| 训练 | 单阶段 PPO、配对 token 对齐、独立策略及无对齐两种对照 |
| 评测 | 六组合完整片段、逐片段失败分类、逐类结果、动作家族 bootstrap 区间、跨种子汇总 |
| 复现 | 配置、环境定义、源码快照、数据摘要、checkpoint、优化器及随机状态、本地 JSONL/TensorBoard |

既有 HEFT 三阶段入口保留；新的正式入口为 `scripts/run_xwbc.sh`，避免混用实验流程。

## 数据准备结果

正式派生目录：`dataset/xwbc/paired_10k_v1`。

| 划分 | 动作 | 帧数 | shard |
|---|---:|---:|---:|
| 训练 | 8,000 | 3,285,826 | 63 |
| 验证 | 1,000 | 384,331 | 8 |
| 测试 | 1,000 | 358,112 | 8 |
| 合计 | 10,000 | 4,028,269 | 79 |

正式选样与规划候选清单 SHA-256 一致。此次格式/数值准入剔除数为零；各片段另外记录最低关键点高度及最大关节速度，供后续物理难度分析。源数据保持原样，机器人头手参考点统一使用当前模型 FK。

机器人最小参考张量保留在 CPU，命令特征以 FP16 常驻 GPU，训练按索引构造 FP32 时间窗口。这是在单 B200 和当前一万条规模下采用的实现选择，后续扩大数据规模时可改为有界命令缓存。

## 运行验证

| 验证 | 实际执行 | 结果位置 |
|---|---|---|
| 共享模型基础链路 | 每机型 16 环境、2 次更新，六路重载检查 | `train_01/` |
| 正式数据接口 | 每机型 2,048 环境、2 次更新，共 262,144 transitions | `train_fullscale/` |
| B200 容量 | 每机型 8,192 环境、2 次更新，共 1,048,576 transitions，六路重载检查 | `train_b200_capacity/` |
| 独立策略 | 每机型 16 环境、1 次更新，并完成验证集 4 条动作的六组合评估 | `smoke_independent/` |
| 无对齐消融 | 同样的短预算及六组合评估 | `smoke_no_align/` |
| 继续训练 | 恢复独立策略的第 1 次更新状态，再完成第 2 次更新 | `resume_01/` |
| 正式数据 checkpoint 评估 | 验证集 4 条动作 × 六组合，输出 24 条评分记录 | `eval_fullscale/` |
| 结果汇总 | 使用独立策略/无对齐短实验的实际结果检查汇总入口 | `summary_check/` |

上述目录均位于 `logs/v0.1/xwbc_validation/`。训练损失及梯度为有限值，已保存的 checkpoint 在对应验证中通过六路确定性输出重载检查。

B200 容量短测两次更新分别约为 36,643 和 27,084 transitions/s。该运行的 PyTorch 峰值分配约 9.54 GB；运行过程的一次设备快照为 29,896 MiB，包含其他 CUDA 分配。原始快照数值记录于开发过程，本表将其作为运行时观察而非显存峰值。

容量短测 G1 恢复计数为 0，Roban 为 1,653。恢复计数保留在每次更新日志，评测将非有限状态作为独立失败类别。正式学习过程结合该计数、动作类别和跟踪效果观察稳定性，定位时可关联数据几何摘要。

本轮吞吐与指标用于确定运行规模、验证更新和评分链路。模型效果比较将在规定预算训练后，依据冻结模型的完整六组合评估形成结论。

## 针对性检查

8 项 unittest 已通过，覆盖：

- 所选命令来源不受其他来源输入变化影响。
- 共享与独立主干的梯度路由及目标动作维度。
- PPO 概率和对齐计算。
- GAE 区分 terminal 与时间截断，优势不跨 reset 传播。
- 动作家族泄漏拒绝与窗口边界隔离。
- 命令表示的水平平移不变性。
- 无负载环境配置及完整语义关键点覆盖。

实际测试命令和输出保存在 `unit_tests.log`；正式脚本经过 Bash 语法及 DRY_RUN 检查，已准备数据也通过候选清单摘要复核。

## 规划到实现的选择

首版采用共享 MLP 和单阶段直接学习，保留独立模型及去掉对齐的对照。模型使用固定物理量缩放与 LayerNorm；命令归一化后保留高度、转向角速度及各 body 速度，本体信息采用固定长度历史。

B200 默认配置设为每机型 8,192 环境、32 步采集、2,500 次更新，与先前每机型 2,048 环境、10,000 次更新具有相同总 transitions。默认每份正式模型约 13.1 亿 transitions，完整三方法三种子对照顺序使用同一张 GPU。

当前正式长跑尚未启动。下一项科研工作是运行共享模型，观察学习曲线及恢复事件，再按相同协议开展完整对照和六组合统计分析。
