# 04 三阶段训练协议

状态：设计；配置/数据尚未实现。沿用HEFT更新分工，不凭latent loss给训练成功标签。

## 0. 公共条件与nominal定义

平地、原Roban质量/惯性/碰撞、原position actuators，gravity=[0,0,-9.81]。所有新训练对照及统一evaluator显式锁定：

| 配置 | v0.1推荐 |
|---|---|
| motor stiffness/damping/armature DR | scale范围[1,1]，实际名义参数取roban.py |
| COM perturb | [0,0] |
| foot material | friction固定当前训练资产名义0.6；solref取实际编译model原值，两端同值，不猜MuJoCo默认 |
| joint offset | [0,0] |
| root velocity perturb | 所有幅值0 |
| wrench / hand load | force0、window load disabled；无payload变化 |
| gravity perturb | std=0，固定名义重力 |
| action alpha / delay | [.9,.9]、max_delay=0；沿用每物理子步滤波，不改官方部署runtime |
| torque limit scale | [1,1]，关闭4→1课程 |
| boot actuator override | 关闭，防止clean pose辅助Student控制 |
| student_motion_randomization | enable=false；paired raw为唯一reference污染源 |
| 本体/command观测噪声 | 第一轮统一置0（含shared q/dq/bias、gyro/gravity、command orientation）；这是受控条件，不声称真实传感器无噪声 |
| initial state | 所有模型共同clean reference初态；train允许原有有界reset扰动，eval按固定init manifest；不算physics DR |
| sampling | 所有新run resample_on_reset=true，失败rewind保持motion，记录unique coverage |
| reference processing | v0.1 consistent clip-before-FK，完成legacy-vs-consistent B0桥接后冻结 |
| finite/DDP | 原防护保留，恢复事件记录为failure，不悄悄重试直到成功 |

nominal不是仅关闭payload或student_motion_randomization。保留退化范围randomization provider满足priv_critic接口；加载后逐字段比较实际sim model与roban.py名义值，避免Hydra字典合并遗漏。禁用的重力/材料对象若有零范围API问题，在overlay适配中解决并测试。训练噪声与初始化随机性、dirty reference随机性分开记录。

Student_train仍按阶段false/true/true，保留原root XY reward差异与loco权重变化；跨阶段只比较同一固定evaluator的success/tracking，原训练return仅阶段内趋势。新T与N-raw-T使用相同Teacher reward/课程，新F与N-raw-F相同Student reward；N-direct/C使用Student reward和相同设置。

## 1. 初始化与预算

主T与N-raw-T加载现有Teacher final的encoder/actor/critic/Adapter/normalizer作为共同warm start。主F链不能用旧final Student偷换新Teacher结果；新A必须来自本次T，新F必须来自本次A。B0/C/N-direct从现有Finetune final初始化，属于另一个共同起点比较。

Warm start不是精确resume：optimizer重新创建，显式设定LR、课程进度、num_updates记录和新增预算；`load_state_dict`会恢复部分meta，`train.py`又按新budget计算progress，必须在日志记录effective行为。建议固定nominal物理与loco终态，Teacher alignment reg从0→.2沿本轮progress继续使用源码规则，所有T/N-raw对照一致；不要误把旧Teacher progress≈1导致的meta当成本轮课程自动延续。

参考pilot预算：每阶段先有界100 rollout核验链路，不压缩正式课程；继承当前`stop_after_rollouts`机制。它是工程验证，不是阶段性能结论。新增正式budget待pilot吞吐、variance与validation曲线后冻结；可从Teacher/Adapt/Finetune各5000 rollout的warm-start预算候选开始讨论，不把历史50K重新训练默认化。合同中正式预算保持null，避免误启动。沿用horizon32/16/32和现有PPO3epoch/8minibatch作为起点；env规模由资源预检确定，正式前固定。

正式至少3个训练seed[0,1,2]，每seed独立整链；可行性pilot先seed0，不把它当多seed证据。每个方案相同调参次数/validation机会。匹配新增transition总数，不用只按rollout数比较16步和32步阶段。N-direct总预算匹配T+A+F（其中A虽然不PPO仍消耗环境样本），同时报告PPO更新数与计算预算，避免声称所有计算量完全一致。

## 2. Stage1：Teacher Training

- 输入：policy=raw reference+可部署反馈；priv=clean reference+既有sim特权；priv_critic=domain常量。
- rollout：原Teacher encoder+Actor，action经同名义控制链作用机器人；状态由真实闭环得到。
- 目标：clean tracking reward+原loco；PPO、entropy、value、symmetry；Teacher表征可估计性reg；Adapter额外MSE训练。
- 更新：encoder_priv、actor_teacher、critic；独立opt_estimator更新Adapter。actor_student不优化。VecNorm按train更新，T/N-raw拥有各自训练统计，初始化来源相同。
- 数据：train S0/S1/S2；reference root不变，污染seed独立于初始化seed。验证固定manifest，不回传梯度。
- 输出：`T/checkpoint_{iter}.pt`、`checkpoint_final.pt`、validation选出的`checkpoint_selected.pt`、normalizer、cfg、合同hash和parent hash。selected通过索引指向原周期文件也可，不复制到科研。
- 验收：同一validation下dirty success/completion与误差相对B0、N-raw-T的配对差；clean与快速动作无未解释退化；数值稳定、coverage充分、参数与finite/DDP检查通过。Teacher差或无增益应记录否定/不确定结果，不能凭reward上升宣布hypothesis成立。

## 3. Stage2：Student / Adapter Training

- parent：本seed本链selected T。from-train checkpoint自动硬复制Teacher Actor到Student Actor；检查复制后参数逐项相同。继承T在Stage1同步学得的Adapter和VecNorm。
- rollout：Student `o_raw→Adapter→Q→Actor_student`，Teacher不控制环境。
- label：在相同Student访问状态上，固定Teacher encoder(clean priv)产生z_T，no_grad；不是固定一份Teacher trajectory数据。
- loss：现有连续latent MSE，2 estimator epochs，symmetry照旧；第一版不增加action loss，action差只诊断。
- 更新：仅Adapter；Teacher Actor、Teacher encoder、Student Actor、critic和VecNorm均固定。定期hash验证。
- 输出：A周期、final、selected checkpoint和连续/量化latent/action/rollout诊断。
- 验收：Lz相对方差/常值预测基线有解释，z无塌缩；实际量化后action差与闭环Student性能接近T的程度；包括S0能力、dirty失败类型和恢复情况。不能以连续MSE下降替代rollout。若A仍差，明确“representation transfer未成立”；可继续F检验是否能补救，但不能改写A结果或越过信息边界。

## 4. Stage3：Student Fine-tuning

- parent：本次A selected，保留Actor/Adapter/normalizer血缘。
- rollout：真实Student raw-only链，训练时可计算clean critic/reward但不得输入Actor。
- 更新：现有Student Actor+critic PPO；Adapter、Teacher encoder/Actor、normalizer固定，quantizer无参数。Stage3不偷偷联合更新Adapter；联合更新仅是N-direct强对照的显式模式。
- reward：沿用Student clean追踪+原loco，root XY滑动target明确标记。reward不是追raw。
- 输出：F周期/final/selected、Student ONNX+JSON+hash、导出一致性报告。
- 验收：同evaluator下F对A的配对收益、F对T gap、F对最强noisy baseline；S0成功/误差/幅值/节奏保持情况；控制饱和与limit事件无用保守动作掩盖。ONNX与Python fixed inputs和实际rollout inputs一致，无priv输入。

## 5. 阶段结束与选模

预算上限和评测间隔在正式前冻结；每阶段看连续validation窗口和多seed变化，不任意规定“提高5%”或“latent低于某数”。先用B0重复测量得到自然波动，冻结clean退化容忍与选模规则，再用于后续选checkpoint。

建议预声明selection：在clean非劣约束候选内按dirty completion/success优先、随后joint/root-relative误差选优，指标处于不确定区间时保留较早checkpoint；预算内未达标也保存final并记录inconclusive。若改变预算或loss，开新run/修订合同，旧结果不覆盖。latents相近/均值reward平台/terminal_count均不单独作为结束判据。

## 6. 需要的新checkpoint与保留项

每seed保留T selected→A selected→F selected/final及周期索引；N-raw同样T/A/F；N-direct与C保留selected/final；可部署F和N-direct/N-raw-F各自export。B0旧Teacher、两份Adapt、Finetune和原ONNX/JSON全部原地保留（路径/hash在provenance）。官方policy0905可作外部参考，不取代同框架baseline。新checkpoint不覆盖旧名路径；研究目录只保存索引。
