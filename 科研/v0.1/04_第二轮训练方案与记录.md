# v0.1 第二轮：统一 HEFT 时间上下文、扩大 Encoder、增加训练预算

日期：2026-10-02（北京时间）。分支：`research/xwbc/v0.1`。继续使用 v0.1 研究定义与数据，第一轮证据保留在 `logs/v0.1/shared_seed0_run01/`。

## 研究目的

在原有共享策略上提供更充分的动作预览与状态历史，增大命令/本体编码容量，并训练 10,000 次更新，检验组合方案对跟踪效果的改善。这里一次更新指采集 rollout 后的一次 PPO 更新周期，内部仍执行 3 个优化 epoch。

当前把时间上下文、编码容量和训练预算作为一组改进共同测试。取得六组合结果后，可使用保留的第一轮配置做单因素对照，分解各项改进的作用。

## 已确定配置

| 项目 | 第一轮 | 第二轮，两机型一致 |
|---|---|---|
| 命令参考偏移 | `[-4,-2,0,2,4]` | `[0,1,2,4,8,12,16,20,-1,-2,-4,-8]` |
| 最远参考未来/过去 | 80 / 80 ms | 400 / 160 ms |
| 本体历史 | 连续 8 个状态时刻，最远回看 140 ms | `[0,1,2,3,4,8,12,16,20]`，9 个时刻，最远回看 400 ms |
| 历史控制动作 | 与状态交错存储，最近 8 个 | 单独拼接最近 8 个已施加动作，与 HEFT 接口一致 |
| Encoder 中间层 / 输出 | 256 / 128 | 512 / 256 |
| 主干输入 / 隐层 | 256 / `[512,512,256]` | 512 / `[512,512,256]` |
| 更新次数 | 2,500 | 10,000 |
| 每机型环境 / rollout 长度 | 8,192 / 32 | 8,192 / 32 |
| 总 transitions | 1,310,720,000 | 5,242,880,000 |

参考窗口取自 HEFT 的 Teacher 参考时刻；本体历史取自其普通 policy 观测配置；动作历史仍为 8。三个来源共用同一参考偏移，两机型共用同一本体历史定义。保留不同来源的关节/骨架语义及各自编码器。

新命令输入维度：Human 3,204，G1/Roban 各 1,908。新本体输入维度：G1 808，Roban 600。两个 256 维 token 拼接进入共享主干，Decoder 仍输出 G1 的 29 维和 Roban 的 21 维动作。特权 critic 的输入分别为 875 和 651 维。

对齐损失继续使用归一化 token 的逐维 MSE。维度从 128 翻倍为 256 后，对齐权重从 1 调到 2，以保持其对成对余弦距离的系数：`lambda * 2 / token_dim`。这项调整补偿维度平均，不额外增强对齐目标。

## 复用与兼容

- 用 HEFT 的 `TensorRingBuffer` 实现本体历史，按指定偏移采样；部分环境 reset 只清空对应行。
- 用 HEFT `JointPosition.get_recent_action_obs()` 读取动作历史，避免额外维护一份动作缓冲。
- 在已有 CommandBank 上配置采样偏移。存储的是逐帧特征，因此复用已编译一万条数据，无需重新转换或复制。
- 环境参考监督仍使用当前帧；actor 的多帧参考由 CommandBank 提供，两种用途分开。
- `cfg/xwbc/train.yaml` 保持第一轮设置，新配置 `cfg/xwbc/heft_context.yaml` 继承它，仅覆盖本轮改动。原有脚本通过 `CONFIG` 选择配置，不新增平行训练框架。
- 旧 checkpoint 按原时间窗口和原历史顺序评估。新模型从头初始化，新输入维度与参数结构写入 checkpoint 和 `observation_contract.json`。

奖励、数据划分、动作缩放、PD、源选择配比、Adam/PPO 超参数和评估定义沿用第一轮。继续使用无负载直接 PPO；本轮未附带恢复域随机化、EMA 或其他课程，以便集中观察上下文与容量改进。
