# HEFT_XWBC 长期研究开发规范

## 适用范围与维护方式

本规范是本项目各版本 AI 协作的共同依据，服务于持续研究、实现和复现。版本分支承载阶段方案，本规范维护跨版本稳定的目标、研究风格与组织方式。

开始工作时，结合用户当前任务读取本规范、相关科研记录和实际代码，确认所处分支与已有改动。按已明确的目标推进；仅在关键决策确实依赖缺失信息时提出聚焦问题，同时继续独立可完成的工作。

本文件保留长期原则。数据字段表、模型映射、超参数、命令、提交信息、运行结果和阶段待办分别维护在数据说明、配置、代码及科研记录中。方案演进时更新对应资料；只有共同工作方式或研究目标发生变化时才修订本规范。

## 研究目标与能力边界

研究核心是让一个共享策略主体利用不同机器人经验，理解不同来源的动作，并控制具有不同形态的目标机器人完成跟踪。允许来源相关的命令编码器与目标机型相关的状态、动作适配模块。

人体、G1、Roban 构成已有动作来源，G1、Roban 构成已有执行对象。随着研究扩展，来源和执行对象可分别增加。始终将“动作来自哪里”与“由哪个机器人执行”作为独立维度，按其组合评估能力。

围绕跟踪质量、稳定性、跨来源一致性、经验共享收益及泛化能力提出研究问题。将已见动作拟合、新动作泛化和新机型适配分别设计为实验；离线输入、在线输入、仿真与真机的条件写入各阶段研究计划。

共享范围在模型设计和实验记录中清楚定义。独立机型策略用于建立对照，共享模块接受不同机型的学习信号，机型适配模块负责执行差异。模型结构和学习方法由实验选择，保留替换主干、表征与优化方法的空间。

## HEFT 基础能力与复用原则

HEFT 提供机器人动作跟踪的工程基础，包括机型资产与配置、仿真环境、动作及观测构建、奖励与终止逻辑、动作数据处理与加载、强化学习训练，以及评估、导出和运行记录工具。

已有训练路线包含 Teacher、Adapt、Finetune，支持特权信息引导；数据和环境侧已有配对参考、采样、随机化与课程机制，训练侧已有并行训练及诊断能力。PMG、WPC 等机制按研究问题和数据条件选用。具体入口及可用条件以当前实现和对应文档为准。

将这些能力作为可复用基线。增加跨来源命令、多机型联合采样和共享策略时，先识别既有模块的职责，再扩展必要接口。使用相同训练框架和支持多个机型配置，与共享策略联合学习分别记录和评估。

保持既有实验可复现，研究改动通过明确的配置和模块边界接入。已有阶段划分、仿真后端及控制接口可在实验依据充分时演进，变更原因、影响和对照结果进入科研记录。

## 数据格式与语义契约

区分源动作格式、统一语义表示和训练存储格式。现有人体与 Roban 数据使用 NPZ，G1 数据使用 CSV；HEFT 训练使用经过适配的动作存储。文件容器与运动语义分别描述，新增来源通过明确的适配层接入。

数据契约应覆盖采样时间、坐标系、单位、旋转表示、根节点定义、关节与刚体名称及顺序、特征语义和来源信息。具体数值与字段定义放在相应数据说明及实现中，由有意义的检查维持一致性。

已有三类动作具有同源、逐帧配对关系，以稳定的动作标识和时间索引维护。数据筛选、裁剪、增强和派生处理保留这一关系及处理记录；新增非配对来源时单独定义监督方式。按名称和语义建立模型映射，区分浮动根、骨盆和末端参考点。

保留原始数据，派生数据使用清晰的版本与来源记录。优先利用已完成的处理成果，转换围绕训练接口的实际需要展开。按任务需要安排格式、数值、几何和时序检查，将检查结果用于确定接入方式。

训练、验证和测试按同源动作家族组织，并在各来源及机型间保持一致。关联增强与重叠片段归入同一集合。说明采样和筛选策略对类别覆盖、动作难度及机型可行性的影响。

## 实验方法

以“问题—假设—方法—对照—指标—结论”组织研究。每项实验明确要回答的问题，选择能区分主要解释的对照，优先改变与假设直接相关的因素。

先建立可运行、可评估的基线，再用适当规模的实验验证新方法，随后扩大数据、模型或训练预算。检查围绕当前改动和实际风险安排，已完成的验证在条件保持一致时继续复用。

评估覆盖动作来源与目标机型的组合，并关注类别及难度差异。联合报告跟踪误差、成功与完成情况、稳定性和计算代价；结合失败片段解释结果。按研究问题选用重复实验、消融和可视化。

控制对照的数据划分、评估协议和训练预算，说明必要的差异。输入信息、未来参考范围、初始化方式及特权监督在实验中明确，评价条件与拟研究的使用方式保持一致。

多机型训练关注共享参数更新、各机型采样份额和接口一致性；时序模型关注历史组织与回合边界。这些问题通过针对性检查和实验处理，保持实现简洁。

每次运行关联代码版本、完整配置、数据及资产版本、随机状态、实际训练量和结果位置。区分权重初始化、继续训练与完整状态恢复，按研究需要选择并记录。

## 分析与表达规范

采用积极、直接、基于证据的研究风格。先说明主要发现，再给出关键证据、解释和下一步。明确区分观测结果、原因假设与后续方案，让读者能据此做决定。

结论与实际实验范围相匹配，用具体条件表达适用范围。遇到尚待解决的问题，直接写清楚待确认的变量、可用依据和下一项验证行动。避免空泛免责、反复否定和过度防御式表达。

优先讨论影响方法选择与结果解释的因素。对小型、可逆调整采用相称的验证，减少重复确认和与任务无关的检查清单。对影响结论的异常主动定位，给出处理依据。

分析指标变化时结合样本覆盖、训练量、随机波动和失败模式。将短流程验证、学习进展和最终评估分别表述。保留负结果及其启发，形成可复用的科研收获。

研究记录说明为什么选择某种方法、实验观察到了什么、这些观察如何影响后续决策。面向用户的汇报以结果和必要依据为主，完整细节留在相应记录中。

## 代码与文件分区

以下路径均相对于仓库根目录。新增内容优先进入已有职责分区，子目录按研究主题或功能建立，随实际需要扩展。

| 分区 | 内容与组织原则 |
|---|---|
| `.SKILL/` | 长期协作规范；维持单一清晰入口，更新共同原则。 |
| `active_adaptation/` | 可复用运行代码；环境、机器人资产、策略学习和数据工具归入各自功能模块。 |
| `cfg/` | 机型、方法和实验配置；通过组合与覆盖表达差异，减少重复配置。 |
| `scripts/` | 数据准备、训练、评估与分析入口；可复用逻辑沉淀到功能模块。 |
| `tests/` | 数据契约、关键行为及集成回归检查，按功能组织。 |
| `docs/` | 稳定的使用说明、接口说明和维护文档。 |
| `科研/` | 研究计划、论文阅读、实验设计、研究笔记、结果分析、决策依据与科研收获。 |
| `logs/` | 实验训练及评估运行产物，包括日志、配置快照、指标、checkpoint 和诊断输出；每次运行独立保存。 |
| `dataset/` | 源动作入口、派生训练数据及必要的数据描述；来源和派生版本清晰关联。 |
| `paper/` | 参考论文；阅读分析与方法取舍记录在 `科研/`。 |

新增代码按职责扩展，在稳定接口处处理机型或来源差异。研究方案通过有含义的模块名与配置标识区分；成熟的公共逻辑及时合并，避免为每个实验复制整套训练代码。

`科研/` 以主题组织长期问题，以阶段或实验标识关联具体记录。 `科研/v0.1/` 的 Markdown 文档采用 `01_主题.md`、`02_主题.md` 等两位序号前缀；新增文档沿用递增编号，已有编号保持稳定。`logs/` 以唯一运行标识组织，关联研究方案及版本。研究记录引用运行结果，稳定操作方法沉淀至 `docs/`。

新实验将输出位置显式指向 `logs/`，沿用旧入口时核对其输出配置。历史产物保留原位置及引用关系，按需要另行整理。大型数据和运行产物采用与代码不同的存储管理方式，Git 重点维护代码、配置、规范及精炼研究记录。

## 跨版本积累与交接

研究版本表示阶段方案与实验边界，通用模块和目录按职责持续维护。具体版本号、阶段预算和当前待办写入研究记录，保持本规范对后续版本适用。

开展新阶段时阅读相关历史结论，明确沿用的基线、新假设与变化因素。旧结论保留实验条件，新结论说明新增证据及其对方案的影响。通过版本控制和配置追踪演进，避免依赖含义模糊的文件副本。

完成一项工作后，留下改动目的、验证结果、产物位置和下一步研究问题。同步受影响的配置说明与研究记录，使后续 AI 能接续决策过程并复现实验。
