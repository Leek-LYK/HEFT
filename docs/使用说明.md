# Roban 三阶段训练

在仓库根目录执行命令，训练环境使用 `.venv`。默认数据集为
`dataset/roban/main/train_50000_v1`，完整参考数据保留在 CPU，各 GPU 只缓存当前窗口。
数据准备契约见 [Roban 数据适配说明](roban_ominisoma_dataset_adapter.md)。

使用六类全量数据、整文件质量过滤和多 shard 训练，见
[全量数据使用说明](roban_full_dataset_v1.md)。全量训练入口为 `scripts/train_roban_full.sh`；
三阶段 pipeline 可通过 `DATASET_GROUPS_FILE` 指定全量 shard 清单。

## 一条命令完成训练

```bash
bash train.sh
```

| 阶段 | 配置入口 | 默认 rollout 数 | 每轮步数 | checkpoint 间隔 |
| --- | --- | ---: | ---: | ---: |
| Teacher | roban_train | 50000 | 32 | 1000 |
| Adapt | roban_adapt | 5000 | 16 | 250 |
| Finetune | roban_finetune | 5000 | 32 | 250 |

默认 GPU 为 `3,4,7`，每卡 4096 个环境。Teacher 学习特权信息控制策略；
Adapt 继承 Teacher actor，只更新适应模块；Finetune 更新 Student actor 与 critic。
每阶段正常结束并生成非空 `checkpoint_final.pt` 后才进入下一阶段。

训练默认关闭 W&B（包括 offline 模式），启用本地 TensorBoard。
正常完成后仍需评估、导出 Student；脚本不会自动部署。

## 配置预算和设备

```bash
CUDA_VISIBLE_DEVICES=3,4,7 PER_RANK_ENVS=4096 \
TRAIN_ROLLOUTS=50000 ADAPT_ROLLOUTS=5000 FINETUNE_ROLLOUTS=5000 \
DATASET=roban/main/train_50000_v1 \
OUTPUT_ROOT=/absolute/path/to/new_pipeline \
bash train.sh
```

`NPROC` 默认等于可见 GPU 数。`MEMPATH` 默认是仓库内 `dataset` 目录。
每阶段全局环境步数 = GPU 数 × 每卡环境数 × 每轮步数 × rollout 数。
上述轮数是预算，应结合奖励、跟踪质量与失败率决定是否延长。
不要只凭 estimator loss 判断 Adapt 已达标。

只检查命令，不启动训练：

```bash
DRY_RUN=1 bash train.sh
```

## 从已有阶段开始

加载 Teacher，依次运行 Adapt 和 Finetune：

```bash
START_STAGE=adapt \
CHECKPOINT_PATH=/absolute/path/to/teacher/checkpoint_final.pt \
bash train.sh
```

加载 Adapt，只运行 Finetune：

```bash
START_STAGE=finetune \
CHECKPOINT_PATH=/absolute/path/to/adapt/checkpoint_final.pt \
bash train.sh
```

选择新的 `OUTPUT_ROOT`；脚本拒绝覆盖已有目录。checkpoint 包含网络、
归一化状态和训练配置，但不含优化器状态，不支持完整优化器状态的精确续训。
同一阶段额外训练可用 `scripts/train.py` 加载本地 checkpoint，明确指定该阶段
`+exp=roban_train/roban_adapt/roban_finetune` 和新增 `total_frames`；
`train.sh` 的 `START_STAGE` 用于加载前一阶段的产物。

## 产物和 TensorBoard

```text
dataset/_audit/roban_ominisoma/roban_pipeline_<timestamp>/
├── pipeline.sh
├── train/
├── adapt/
└── finetune/
    ├── command.txt
    ├── console.log
    ├── cfg.yaml
    ├── ppo.py
    ├── checkpoint_*.pt
    ├── checkpoint_final.pt
    └── tensorboard/
```

周期文件名使用从零开始的循环索引，精确更新次数查看 checkpoint 的
`policy._meta.num_updates`；正常结束总会保存最终 checkpoint。

```bash
.venv/bin/tensorboard --logdir dataset/_audit/roban_ominisoma --port 6006
```

关注每步奖励、适应损失、回合长度和终止原因。`rollout/terminal_count_global`
包含失败和正常截断，不等于跌倒次数；`train/stats/*` 是 rank 0 的回合统计。

## 评估、校验与导出

Teacher 定量评估（会运行仿真）：

```bash
MEMPATH="$PWD/dataset" .venv/bin/python scripts/evaluate_roban_teacher.py \
  --checkpoint /absolute/path/to/teacher/checkpoint_final.pt \
  --dataset roban/main/train_50000_v1 \
  --output /absolute/path/to/new_evaluation
```

`verify_roban_checkpoint_roundtrip.py` 可验证两次加载后的固定输入动作一致性，
该工具也会构建仿真环境。`scripts/data_process/validate_roban_shard.py`
用于校验生成数据的 manifest、张量及采样 FK。

完成 Finetune 后应评估并导出 Student。目前 `scripts/eval.py --run_path`
仍通过 W&B 下载运行产物，尚不支持直接传本地训练目录。不要把本地目录
当作 W&B run path；本地导出入口需要另行适配。

导出目录为 `scripts/exports/` 下的新目录，应完整保留 ONNX、可能存在的
外部权重文件和 `policy.json`。Roban Student 部署接口为 1313 维观测输入、
21 维 action 输出；包含观测归一化、适应模块、40 维量化 latent 和 Student actor。

## 训练稳定性

保留非有限值恢复、观测 finite gate 和 DDP 同步检查。仿真恢复不代表错误消失，
应同时观察恢复频率和控制表现。Roban 的 `njmax=768` 用于大数据集约束容量；
其他机器人的默认值不变。短时诊断入口 `roban_smoke_*` 和相关回归测试保留，
正式训练使用普通 `roban_*` 配置。
